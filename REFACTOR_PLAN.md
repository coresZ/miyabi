## 0. 原则

1. **不做过度防御**。Miyabi 是自托管、单用户工具，API 不设防是有意的设计：访问密码只是前端入口门，不保护 API。所以威胁模型里没有"恶意调用方"。
   - 只修正常使用下会出错的问题：数据写错、功能失效、资源随时间耗尽。
   - 不为恶意输入、极低概率的并发、进程即将退出的路径写代码。
   - 已有的过度防御视为负担，删除。典型：字幕下载的 SSRF 拨号拦截防的是 API 调用方自己，还把本机代理一起挡掉了（D1、X1）。
2. **一个概念一份实现**。第 2 节是统一性的标尺，偏离即视为问题。
3. **契约变更显式**。改 HTTP 响应形状、query key、任务 payload 时，同一提交改前后端并更新黄金文件。
4. **测试不固化错误行为**。修缺陷时同步改掉断言错误行为的测试（如 `javdb/transport_test.go:103`）。网络层测试走真实 transport 加 `httptest`，不替换 client；D1 就是因为测试换了 client 才漏掉。
5. 沿用 AGENTS.md：不自行安装依赖（需要时列出并等确认，见 E4），不擅改 README，不自动提交，提交信息用英文。

## 1. 架构基线

### 1.1 包布局（现状）

```

  syncx/                     ContextLock

  drive/                     115 账号、挂载目录、Session
```

### 1.2 核心机制（保留）

- `drive.Session`：承担全部 115 访问。`Commit` 持提交锁复查挂载目录与授权版本，`CommitAccount` 只复查凭据。
- `tasks.Handler` + `FinishedHook`：修订号在完成事务内返回，提交后发布。
- `magnet.Source`：按番号提供磁力，JavDB 与 JavBus 各实现一份。
- 身份：JavDB ID 是唯一目录身份，JavBus 只按番号补充。

## 2. 编码规范

### 2.1 Go

| 项        | 规范                                                                                                                                                                                                                                                                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 服务结构  | `type Service struct`；构造函数 `New(...) *Service`；数据库字段 `db *ent.Client`                                                                                                                                                                                                                                                                              |
| 接收者    | 一到两个字母：Service 用 `s`，Client 用 `c`，Drive 用 `d`                                                                                                                                                                                                                                                                                                     |
| 构造函数  | 只装配，不做 I/O、不起 goroutine、不订阅事件；后台工作由 `app.Run` 启动                                                                                                                                                                                                                                                                                       |
| 依赖注入  | 只走构造参数，不用 setter；循环依赖用调用方定义的接口打断                                                                                                                                                                                                                                                                                                     |
| 命名      | 参数不遮蔽包名（`pan DriveManager`、`tasks *tasks.Service` 之类改掉）                                                                                                                                                                                                                                                                                         |
| 日志      | 全局 `slog.*Context`，不传 logger 参数。key 用 snake_case：`task_id / request_id / movie_id / directory_id / error`。message 描述动作，不用任务名充当                                                                                                                                                                                                         |
| 错误      | 用户只看文案，不看原文：面向用户用 `domain.E(kind, 中文文案, cause)`，没有文案的错误由 API 层按状态码给通用中文提示，完整错误只进日志；基础设施错误类型实现 `DomainKind() / PublicMessage()`；输入校验一律 `KindInvalid`；无格式参数用 `errors.New`；`fmt.Errorf` 包装必须带 `%w`；不吞错误（`_ =`、`if err == nil { ... }`），确实可忽略的写一行注释说明理由 |
| 事务      | 依赖挂载目录的写入走 `sess.Commit`，只依赖账号的走 `CommitAccount`，其余用 `ent.WithTx`；单条语句不开事务                                                                                                                                                                                                                                                     |
| 通知      | 只在提交后发布；事务内只收集 `tasks.Change`                                                                                                                                                                                                                                                                                                                   |
| 上游 HTTP | 客户端只从 `netx` 创建；响应体一律经 `netx.ReadLimited` 读取（超限返回错误，不截断）；只重试幂等请求                                                                                                                                                                                                                                                          |
| 测试接缝  | 不导出只为测试存在的 API；用包内测试文件或未导出字段                                                                                                                                                                                                                                                                                                          |
| 别名      | 不用 `type X = Y`                                                                                                                                                                                                                                                                                                                                             |
| 常量      | 外部协议的魔数（115 离线状态码、磁力前缀、JSON path）在所属包命名一次                                                                                                                                                                                                                                                                                         |

### 2.2 HTTP API

- 成功且无返回体的响应一律 `204`，由新增的 `noContent(c, err)` 输出。它替换 `null`、`{"success":true}`、`{"updated":true}`、`{"deleted":true}`、`{"released":true}`；`{"removed": n}` 这类有信息量的保留。
- 更新接口返回更新后的规范化资源，形状与 GET 相同。
- 请求 DTO 一律用命名类型，放在 handler 文件顶部；`form` / `binding` 标签只出现在 `api` 包。
- 需要禁止缓存的路由按组挂 `noStore()`。

### 2.3 前端

| 项           | 规范                                                                                                                                                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| query key    | 每个 api 模块定义一个 key 工厂（现有 `libraryKeys / discoverKeys / …`），跨模块使用时导入工厂，不手写字面量；只在一处使用的 key（`auth`、`play`）可以保留字面量                                                                |
| 服务端状态   | 只放在 TanStack Query。自写缓存只允许两类：批量 loader（`movie-state-cache`）和写后同步 store（`browse-history-store`）                                                                                                        |
| 刷新策略     | 每个资源二选一：推送驱动（SSE `setQueryData` 或 invalidate），或挂载即刷新；不叠加，也不再额外开窗口聚焦刷新                                                                                                                   |
| mutation     | 默认在 `onSuccess` 里 `return invalidateQueries(...)`，让 isPending 覆盖到重新拉取结束；只有响应就是完整新状态、而且没有其他 key 受影响时，才直接用响应写缓存。两者不叠加                                                      |
| 设置保存     | 悲观更新：请求进行中禁用控件，成功后刷新；不做乐观更新和回滚                                                                                                                                                                   |
| 提示         | 同一次失败只提示一次。对话框内的 mutation 只显示 inline 错误；其余情况下，所有调用方都要同一句话时可以在 hook 里 toast，否则由组件 toast                                                                                       |
| 错误文案     | `api/client.ts` 里只有一个 `errorMessage(error, fallback?)`：`ApiError` 取后端文案，其他错误（包括 `Failed to fetch`）一律返回中文兜底。401 时让 115 账号失效的逻辑统一放在 `main.tsx` 的 `QueryCache / MutationCache.onError` |
| 列表状态     | 页码、tab、筛选放 URL search params（`validateSearch`）；发现页例外，沿用 `stores/discover.ts`（决定见 12.2）                                                                                                                  |
| 查询结果传参 | 倾向让子组件直接接收 `UseQueryResult`，不拆成多个 flag；数据来源不同的场景不强求                                                                                                                                               |
| 禁用查询     | 用 `skipToken`，或者在有 id 时才挂载子组件；不用空 id 加 `enabled: false`                                                                                                                                                      |
| 导入         | 同目录用 `./`，跨目录用 `@/`；不用 `../../` 形式的相对路径，也不用 `.ts` 后缀；不用 barrel                                                                                                                                     |
| ARIA         | 按 `f19b11a` 的决定不写自定义 ARIA 和 `role`；播放器和预览图对话框有意不加 `DialogTitle`                                                                                                                                       |

### 2.4 UI 原则

目标是干净、整洁、可靠，全站一种 UI 风格。能精简的就精简，能自然复用的就复用，不做过度设计。

**抽取的门槛**

- 同一段有状态逻辑出现 2 次，或者同一段非平凡的 JSX 或类名出现 3 次，才抽取。
- 只在一个文件内重复的，抽成文件内的局部组件或函数；跨 feature 使用的才放进 `components/`。
- 共享组件的 props 只接收真实存在的差异。在已经有 2 个调用方需要之前，不开 children 插槽、配置对象或布尔开关。
- 不为了将来的复用预先抽象，不写泛型工厂（例如 `settingsQuery<T>`）。
- 看起来重复、但每份语义不同的，保持原样（例如三个订阅按钮，见第 9 节）。

**文件粒度**

- 只有一个调用方的小组件、只包一两行的 hook、只为 node 测试拆出来的文件，都并回调用方（X9）。
- 文件大小以职责为准，不以行数为准。现有的大文件（`preview-viewer`、`playback-player`、`watch-progress-writer`）职责内聚，不拆。

**样式**

- 颜色只用主题 token，包括 `success / warning / info`。不写原生调色板（`zinc-*`、`white/*`、`orange-*`）、任意值（`text-[10px]`）或 oklch 覆盖。图片上的遮罩（`bg-black/40`）和二维码底色例外。
- 优先用组件变体和尺寸（`size="xs"`），不要用一串 className 去抵消变体。卡片点击区用原生 `<button>` 或 `<Link>`，不用 ghost Button 再覆盖掉它的样式。
- 按钮内的图标不写尺寸（Button 已经统一了）。图标用 `XxxIcon` 命名；加载中用 `LoaderCircleIcon animate-spin`；刷新中让 `RefreshCwIcon` 自己旋转。
- 条件渲染用 `? : null`。
- 普通容器描边用 `border`，Card 保持自带样式。卡片与面板用 `rounded-2xl`，缩略图用 `rounded-xl`。长文本换行用 `wrap-break-word`。
- 图标按钮的提示用 Tooltip，不用原生 `title`。

**状态展示**

- 页面级：`EmptyState / ErrorState`。
- 区块和设置行内：`Skeleton` 加 `InlineError`。不把 `ErrorState` 放进设置行，它是整块大图。
- 骨架屏与真实布局保持一致（圆角、结构）。骨架可以复制布局写法，不共享布局常量。

## 12. 决定记录

### 12.1 延续的决定

**架构**

- 包名沿用 `database`；`syncx` 放 `ContextLock`，并新增 `Broadcaster`（R1）。
- 错误模型：`domain.Error` 不实现自定义 `Is`，哨兵按指针身份匹配；基础设施错误类型通过 `DomainKind() / PublicMessage()` 接入，不在业务层逐个翻译。
- 任务引擎：`tasks.Queue` 不含领域规则；修订号由 `FinishedHook` 以 `tasks.Change` 返回，提交后统一发布。
- 挂载：drive 先持久化并切换版本，再在提交锁内同步发布 `MountChanged`，任一监听者出错就回滚；监听者不得经由 drive 开会话或提交。挂载触发的扫描只复用 `Queued`，手动重扫复用 `Queued + Running`。
- `drive.Session` 承担全部 115 访问；`CommitAccount` 只复查凭据，换目录后离线任务仍能落账。
- 番号识别：不引入前缀字典。`codeid.IsEquivalent` 分三级容差；`ResolveMovieID` 严格全等优先，其次格式等价，最后去零退避；多个候选时拒绝。
- 业务包边界由 `deps_test` 强制：跨包 DTO 放 `domain`，跨包 ent 查询范围放 `database`。
- 不用类型别名。
- `config`：对外只有四个环境变量；`Runtime` 只放在组合根有注入点的常量。

**网络**

- 一个开关、一个地址：开启时 JavDB 与 JavBus 走代理，115 永远直连（D5 修正实现）。代理密码不脱敏。JavBus 只有一个端点。

**产品**

- JavBus 默认关闭。磁力的站方标注与名称推断分开记录，Picker 对推断出的属性减半计分。
- 订阅支持影片与演员，共用一个每日检查时间。用户重复添加已入库或过期的影片视为重新订阅；演员检查派生的添加绝不重置已有订阅。演员订阅以订阅时的作品页为游标基线，之后只把未见过、且不早于水位线一个月的作品当新作。

**前端**

- 样式与动效以现状为基线，包括徽章的 `library / frosted` 变体、分页器和订阅页。字幕菜单的磨砂暗黑风格通过 token 实现（C29）。

### 12.2 本轮新增（2026-09-23）

- **API 不设防是设计**，访问密码只是前端入口门。
- **不做过度防御**（原则 1），据此删除 SSRF 拨号拦截（X1）。
- **用户只看中文文案**：没有 `PublicMessage` 的错误按状态码显示通用中文提示；完整错误、原因和请求 ID 只写日志；任务的 `error` 字段只存文案（C3）。上一版"未分类错误原文透出"的决定作废。
- **UI 原则**（2.4）：不过度封装，也不复制粘贴；全站一种风格，能精简就精简，能自然复用就复用。
- **播放器与预览图对话框有意不加 `DialogTitle`**，其余沿用 `f19b11a`：不写自定义 ARIA。
- **前端测试换 Vitest**（E4，已确认）。
- **日志统一用全局 slog**，不注入 logger（C2，已确认）。
- **`subtitle` 定位为内核层**，与 drive、tasks 同级（C8，已确认）。
- **Dockerfile 保持 root 运行**，删除没用上的用户创建（E1，已确认）。
- **订阅按钮三处语义各自保留**：上一版 R26 撤回，理由见第 9 节。
- **发现页状态保留在 store**，其余列表页用 URL。
- **任务池单 worker**（`TaskPoolWorkers = 1`）：并发相关的优化以此为前提评估。
- **SubtitleQueue 并入 tasks**：全仓只有一套任务系统（R14）。
